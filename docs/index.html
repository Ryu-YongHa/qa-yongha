실무 QA Jira 버그 리포트 작성 핵심 가이드

개발자가 한 번에 이해하고 재현할 수 있는 좋은 티켓 작성법

1. 명확한 요약 (Summary) 규칙

[카테고리/위치] + 무엇을 할 때 + 어떤 문제가 발생하는지 한 문장으로 요약합니다.

나쁜 예: 상점 버튼이 안 눌려요
좋은 예: [로비/상점] 골드 부족 상태에서 패키지 구매 버튼 터치 시 무반응 현상

2. 심각도(Severity) vs 우선순위(Priority)

  • 심각도 (QA 기준): 버그가 시스템/게임에 미치는 기술적 타격 (예: 크래시, 데이터 유실 = Critical)
  • 우선순위 (비즈니스 기준): 수정해야 하는 시급성 (예: 오탈자라도 메인 타이틀 로고 오타면 Priority는 Highest)

3. 표준 버그 리포트 본문 구성 (5대 필수 요소)

[사전 조건 / 환경] 빌드 v1.0.4 / Windows 11 / 튜토리얼 완료 계정

[재현 경로 (Steps to Reproduce)]
1. 메인 로비 우측 상단 [인벤토리] 아이콘 클릭
2. '회복 포션' 아이템 선택 후 [분해] 버튼 클릭
3. 수량 조절 슬라이더를 최대로 드래그 후 확인 클릭

[기대 결과 (Expected Result)] 아이템이 정상 분해되고 골드가 지급되어야 함

[실제 결과 (Actual Result)] 팝업이 닫히지 않으며 'Error Code: 502' 노출 후 조작 불가

[재현 빈도] 5/5 (100% 재현)
